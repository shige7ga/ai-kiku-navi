# AIきくナビ

## 概要

AIきくナビは、IT初学者がAIへの質問や相談内容を整理し、伝わりやすいプロンプト（AIへの依頼文）を作成するツールです。

用途を選び、必要事項を入力するだけで、AIにそのまま渡せる文章を作れます。ログインは不要で、PC・スマートフォンのブラウザーで利用できます。

## なぜ必要なのか

学習や開発でAIに相談するとき、「何を伝えればよいかわからない」「状況をうまく説明できない」「欲しい形式の回答が得られない」と悩むことがあります。

AIきくナビは、用途ごとに入力項目と記入例を用意し、目的・現在の状況・補足情報・希望する回答形式を整理する手助けをします。質問のたびに一から文章を考える負担を減らし、よく使う依頼文は保存して再利用できます。

## 機能一覧

### Webデザイン用（メイン機能）

- アプリ名のみのヘッダー内にある「Webデザイン用 / 学習用 / GitHub用 / 保存済み」で切り替えます。
- 7つのプリセットから色・フォント・角丸・影・余白・ボタン・カードをまとめて設定し、個別に調整できます。
- PCの1〜3カラムと配置、カードの置き場所、スマートフォンのヘッダー・下部メニューなどを選べます。
- PC / Tablet / Mobileの簡易プレビューを画面上部に小さく並べ、PC・スマートフォンともスクロール中はstickyで表示します。
- 全項目が任意です。「Promptを作成」で初期設定のままでも生成できます。
- 参考URLと参考にしたい部分を複数追加・削除できます。使用技術・避けたいデザイン・その他の指示も生成文に含めます。URL先にはアクセスしません。
- 目的・ターゲット・UI・配置のプルダウンで「その他」を選んだときだけ自由入力を表示します。選び直すと自由入力の内容は生成文に含めません。

### 既存の7種類の用途別テンプレート

PR文作成は「GitHub用」、それ以外は「学習用」にあります。

| 用途 | 整理できる内容 |
| --- | --- |
| 技術的な質問 | 知りたいこと、学習状況、調べたことや不明点 |
| エラー相談 | やりたいこと、エラー内容、実行環境、試したこと |
| PR文作成 | 変更内容、変更の背景、動作確認の内容 |
| Notion用まとめ | まとめたいメモ、用途や読む人、残したいポイント |
| Codexへの実装依頼 | 実装したい機能、現在の技術構成、制約や完了条件 |
| アイデア整理 | アイデア、対象の人や悩み、条件や迷っていること |
| 文章要約 | 要約したい文章、用途や読む人、注目点や文字数の目安 |

### プロンプトの生成・編集・コピー

- 選んだ用途に合わせた入力フォームを表示します。
- 入力内容から、目的・依頼内容、前提・現在の状況、補足情報をまとめたプロンプトを生成します。未入力の項目は省略します。
- 回答形式と詳しさを選べます。指定しないこともできます。
- 生成した本文は画面上で編集し、ボタンひとつでコピーできます。

### 自分用テンプレートの保存・再利用

- 本文に名前を付けて、ブラウザーのLocalStorageに保存できます。
- 名前・本文・作成日時・識別用IDを保存します。
- 保存済みテンプレートを一覧から選び、本文を読み込んで編集・コピーできます。

## 使い方

### Webデザインのプロンプトを作る

1. 「Webデザイン用」でプリセットを選びます。
2. 必要な項目だけ変更し、3端末のプレビューで見た目を確認します。
3. 「Promptを作成」を押し、結果欄で編集・コピー・保存します。

選択内容をフロント側のテンプレート文字列に反映して生成します。AI APIは使いません。
生成文は、指定技術とデザイン条件を使った動作するレスポンシブWebページのコードを、必要なファイルごとに出力するよう要求します。不足する細部は一般的な構成で補完し、長い説明より実装コードを優先させます。
Tabletは最大2カラムに整理し、3つ目の領域は下へ折り返します。
プレビューは簡易的な構成図であり、生成サイトの正確な再現ではありません。
「その他」の自由記述はPromptへ反映し、プレビューは標準的な形で表示します。

### 学習用・GitHub用のプロンプトを作る

1. 「何を手伝ってほしいですか？」から用途を選びます。
2. 表示された項目に入力します。最初の項目だけ必須で、それ以外はわかる範囲で入力できます。
3. 「回答形式」と「回答の詳しさ」を選びます。
4. 「プロンプトを生成」を押します。
5. 「生成したプロンプト」の内容を確認し、必要に応じて編集します。
6. 「プロンプトをコピー」を押し、利用するAIの入力欄に貼り付けます。

このアプリが行うのは依頼文の作成までです。AIへの自動送信や、AIによる回答の生成は行いません。

### 保存して再利用する

1. 生成結果の下にある「自分用テンプレートの名前」を入力します。
2. 「この本文を保存」を押します。
3. 次に使うときは「保存済み」タブの「自分用テンプレート」一覧の「再利用」を押します。
4. 結果欄に読み込まれた本文を必要に応じて編集し、コピーします。

保存対象はその時点の本文です。再利用時に用途別フォームへ入力内容を復元する機能はありません。再利用した本文を編集して保存すると、別のテンプレートとして追加されます。

保存内容は同じブラウザーで利用でき、別の端末やブラウザーには同期されません。ブラウザーのサイトデータを削除すると、保存したテンプレートも消えます。

### ローカルで起動する

Node.js 24系とnpmを用意し、プロジェクトのディレクトリで実行します。

```bash
npm ci
npm run dev
```

起動後、ターミナルに表示されるURL（通常は `http://localhost:5173`）をブラウザーで開きます。

Dockerを使う場合は、Docker Composeが利用できる環境で次を実行します。

```bash
docker compose up --build
```

ブラウザーで `http://localhost:5173` を開きます。


## コンポーネントとデータ

- `App.tsx`：カテゴリ、入力状態、生成結果、既存の保存・再利用処理を管理。
- `AppHeader` / `PromptTabs`：アプリ名と4カテゴリの切り替え、キーボード操作。
- `SelectField`：プルダウンと「その他」選択時の自由入力。
- `ReferenceSites`：複数の参考サイトの入力・追加・削除。
- `DesignForm`：入力フォーム。`PresetSelect` / `ColorSettings` / `LayoutSettings`で設定ごとの責務を分離。
- `DesignPreview` / `DevicePreview`：3端末の構成図。
- `TemplateForm`：従来の学習・GitHub用フォーム。
- `PromptResult`：本文編集、コピー、名前を付けた保存。
- `src/design/settings.ts`：型、初期値、プリセット、端末レイアウト、Prompt生成関数。

状態管理はReactのuseStateです。保存は既存の`ai-kiku-navi.templates`キーと形式を維持します。
保存対象は本文で、Webデザイン設定自体の復元や端末間同期は行いません。

## 検証

Node.js 24系で以下を実行します。追加のテストライブラリは不要です。

```bash
npm run lint
npm run typecheck
npm test
npm run build
```

Node標準テストと既存のTypeScript・Reactを使用し、17ケースを確認します。
タブ操作、7プリセット、カラム・カード配置、カラーの3端末への反映、モバイル設定、
未入力の生成、不正カラーの制御、生成文への入力反映、結果欄の操作、既存テンプレート、
保存互換性・保存失敗、Clipboard APIの成功・失敗を対象にしています。
加えてヘッダー、その他の条件付き入力と生成文への反映、複数参考サイトの操作、実装コードを求める指示を確認します。
コンポーネントのHTML出力とイベント処理を検証するテストで、実ブラウザーのE2Eテストではありません。

実ブラウザーでは以下も確認してください。

- キーボードでタブを切り替えられ、フォーム入力が保持されること。
- PC・スマートフォンでスクロールしても上部のプレビューが見え、画面から横にはみ出さないこと。
- 生成後に結果欄へ移動し、編集した本文をコピーして他の入力欄に貼り付けられること。
- 保存後、ページ再読み込みと「保存済み → 再利用」で本文が復元されること。
